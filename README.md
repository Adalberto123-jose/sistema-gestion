# sistema-gestion

Estructura inicial para el proyecto final de Bases de Datos. El tema, el lenguaje de la API y el motor de base de datos quedan pendientes de definir con el equipo.

## Carpetas

- `app/`: código de la API o microservicio(s).
- `sql/`: scripts del esquema, funciones, procedimientos, vistas, triggers y datos de prueba.
- `docs/`: diagrama ER, arquitectura, diccionario de datos e informe (máximo 5 páginas).
- `presentation/`: diapositivas para la sustentación.

## Requisitos que debe cubrir el proyecto

- Problema claramente definido.
- Diagrama ER/relacional con mínimo seis tablas relacionadas y normalizadas hasta 3FN.
- Contenedor de aplicación y contenedor de base de datos, orquestados con Docker Compose.
- API REST con operaciones CRUD que consuma la lógica de la base de datos.
- Al menos dos funciones, dos procedimientos almacenados, dos vistas (una combinando varias tablas) y dos triggers.
- Datos de prueba y README con instrucciones para levantar el proyecto.

Cuando el equipo elija el tema y las tecnologías, completar las carpetas con la implementación concreta y actualizar este README con los comandos de instalación, ejecución y pruebas manuales.
